# LLM and hybrid methods

The LLM agent gives the model a fixed chemist system prompt and a user message that places the reaction description and the option list first, then the experiment history, and asks for exactly k new labelled experiments. Returned labels are matched to rows in the measured condition table; combinations that are missing, duplicated, or already evaluated are dropped, and each kept pick is logged with its one-sentence reason. Responses are written under data/cache/llm and reused on later runs, so a campaign can finish from the cache when OPENAI_API_KEY is unset. Hybrid asks the named model for a shortlist of 20, keeps the unevaluated rows, and ranks that shortlist by the surrogate's upper quantile (q90), filling any shortfall, including an empty shortlist, from q90 over the rest of the pool. The anonymised control hides chemical names and SMILES behind labels such as "Ligand option 1", so a gap versus named mode is evidence about chemistry knowledge versus pattern matching on the observed yields. These public reaction datasets may already have been in the model's training data, and anonymisation only partly addresses that. The gpt-6-luna ledger in results/llm_usage.json records 534306 total tokens from 198 live calls and 18 cache hits.
